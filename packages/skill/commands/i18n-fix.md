---

交互式修复项目中的硬编码中文字符串。

## 执行步骤

1. 确定目标路径：使用用户提供的路径参数，如果没有提供则使用当前工作目录
2. 调用 MCP tool `i18n_scan_hardcoded` 获取硬编码中文列表
3. 如果没有发现硬编码中文，提示用户项目已完成 i18n 改造
4. 如果发现硬编码中文，逐个（或按文件分组）展示并询问用户：
   - 为每个硬编码字符串生成语义化的 i18n key（如 `common.confirm`、`userProfile.editButton`）
   - 展示替换后的代码预览（将中文替换为 `t('key')` 或 `$t('key')`）
   - 询问用户是否确认替换
5. 用户确认后执行替换：
   - 修改源文件：将硬编码中文替换为 t() 调用
   - 更新语言包：在 zh-CN.json 中添加对应的 key-value
   - 如果文件中没有 useI18n()，自动添加导入
6. 替换完成后，运行 `/i18n-validate` 验证结果

## Key 命名规范

生成 i18n key 时遵循以下规范：
- 使用 camelCase 格式
- 按模块/页面分组（如 `userProfile.xxx`、`orderList.xxx`）
- 通用文案使用 `common.xxx`（如确认、取消、提交）
- 按钮文案使用 `xxxButton` 后缀
- 标题使用 `xxxTitle` 后缀
- 提示信息使用 `xxxTip` 或 `xxxMessage` 后缀

## 注意事项

- 每次只修改一个文件，修改完成后再处理下一个
- 跳过不可转换的中文（后端值、图片文字等）
- 确保 t() 调用在响应式上下文中（使用 computed 包裹静态对象中的 t()）
- 修复前确认项目已有 i18n 配置（useI18n 已安装）
- 如果用户说"全部替换"，可以批量处理，但仍需展示变更摘要
